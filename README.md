# משפך שאלון: "מחשבון ההפסדים השקט" לרואי חשבון

משפך Quiz Funnel שמיועד **למשרדי רואי חשבון ויועצי מס**. המסר המרכזי: המערכת משווה אוטומטית בין כמה כסף שילמו לרואה החשבון לבין כמה חייבים לו, אומרת בדיוק מי חייב וכמה, ודואגת לגבייה אוטומטית, וגם בקשת חומרים מהלקוחות באופן אוטומטי. הוא בנוי מ-3 דפים סטטיים.
העיצוב בהשראת noamgamliel.com: ירוק אמרלד עמוק (#0B2E24), קרם וזהב (#F4B740), ופונטים Rubik + Heebo.

| קובץ | מה זה |
|---|---|
| `index.html` | דף 1: דף הנחיתה, השאלון (5 שאלות, אחת בכל מסך), מסך "מחשב..." וטופס ליד |
| `results.html` | דף 2: התוצאות האישיות, הדליפה הגדולה, הפתרון, הצעת הסנדק (ערימת ערך + בונוסים), אחריות, דחיפות ויומן Calendly |
| `thank-you.html` | דף 3: אישור הפגישה, 2 צעדי הכנה, מה יקרה בשיחה ווואטסאפ |
| `config.js` | **כל ההגדרות במקום אחד** (שם, Webhook, Calendly, וואטסאפ, תעריף שעה, מחסור) |
| `styles.css` | מערכת העיצוב המשותפת |
| `google-apps-script.gs` | קליטת הלידים ל-Google Sheets (הוראות בראש הקובץ) |

## הזרימה
1. הגולש עונה על 5 שאלות ← מסך "מחשב" ← טופס (שם וטלפון בלבד).
2. הליד נשלח ל-`leadWebhookUrl` עם כל התשובות והחישוב. התוצאה נשמרת ב-sessionStorage, ומשם עוברים ל-`results.html`.
3. דף התוצאות מציג את המספרים האישיים. בקביעת פגישה ב-Calendly יש מעבר אוטומטי ל-`thank-you.html`.
   מומלץ להגדיר את אותה הפניה גם בהגדרות האירוע ב-Calendly (Confirmation page ← Redirect).

## לוגיקת החישוב
- **שעות בחודש (X)** = ש2 רדיפה אחרי לקוחות (4/10/22/35) + ש3 איסוף חומרים לדיווח (1/4/10/16) + ש4 "כמה זמן לדעת כמה חייבים לך" (0/2/5/8), מעוגל
- **הפסד חודשי (Y)** = X × `hourlyRate` (ברירת מחדל ₪300 לשעת רו״ח)
- **שכר טרחה שלא נגבה** = ש1 (5,000 / 20,000 / 55,000 / 100,000, אמצע כל טווח)
- **הדליפה הגדולה**: אם ש1 היא 30 אלף ומעלה, הדליפה היא "שכר טרחה תקוע". אחרת, הרכיב עם הכי הרבה שעות.
- **ש5** מתאימה אישית את כרטיס "מה תעשה עם הזמן".

הוספתי את ש4 לחישוב השעות, כי כל תשובה אמורה להשפיע על התוצאה. כדי להסיר אותה, מחקו את `match` ב-`compute()` שב-index.html.

## ⚠️ לפני העלייה לאוויר
1. **`config.js`**: `leadWebhookUrl` (ה-Webhook של Make), `calendlyUrl` ומספר וואטסאפ אמיתי.
2. **ערימת הערך** (סוכן גבייה ₪4,000/חודש, רודף וואטסאפ ₪1,500, מבקש חומרים ₪1,200, דאשבורד ₪800, בונוסים ₪6,100, סה"כ ₪96,100) היא הערכה שלי. צריך לאשר מול המחיר האמיתי.
3. **האחריות המשולשת** היא התחייבות משפטית: (א) 30 יום, המערכת מממנת את עצמה או שלא משלמים, (ב) 90 יום, פי 3 או החזר מלא, (ג) פיצוי על זמן השיחה. לנסח רק מה שבאמת מתחייבים אליו.
4. **המחסור** (`spotsLeft`, `spotsPerMonth`) חייב להיות אמיתי. אם אין מגבלה: `spotsLeft: null`.
5. **הבטחה בטופס:** "מפת דרכים מבוססת AI". בדף התוצאות היא מסופקת כמפת דרכים ל-30 יום בשיחה. אם רוצים לשלוח אותה אוטומטית (PDF או וואטסאפ), זה נבנה ב-Make.
6. **ההמלצה בדף התודה** היא placeholder. להחליף או למחוק את `#testimonial`.
7. מדיניות פרטיות ותנאי שימוש (עדיין לא קיימים) וקישור אליהם מהטופס.
8. פיקסל Meta / GA: הקוד שולח `QuizStart`, `QuizComplete`, `Lead` ו-`Schedule` אם `fbq`/`gtag` מותקנים.

## Webhook ל-Make (FixDigital CRM + וואטסאפ)
הטופס שולח POST עם JSON שטוח (`Content-Type: application/json`). אם הדפדפן חוסם (CORS), הוא שולח שוב את אותם שדות כ-`application/x-www-form-urlencoded`. Make מפרק את שני הפורמטים לשדות באופן אוטומטי.

| מפתח | דוגמה | הערה |
|---|---|---|
| `event` / `source` | `quiz_lead` / `yitra0_loss_quiz` | לסינון בתרחיש |
| `submitted_at` | `2026-09-24T07:26:00Z` | ISO |
| `name` / `first_name` | `יוסי לוי` / `יוסי` | `first_name` להודעות וואטסאפ |
| `email` | ריק | הטופס לא אוסף אימייל (רק שם + טלפון). המפתח נשאר כדי שהמיפוי לא יישבר |
| `phone` / `phone_intl` | `050-1234567` / `972501234567` | `phone_intl` לוואטסאפ ול-CRM |
| `q1_answer` … `q5_answer` | טקסט התשובה המלא | `q1_question` … `q5_question` = כותרת השאלה |
| `estimated_loss` | `7500` | ₪ לחודש (מספר) |
| `estimated_loss_yearly` | `90000` | ₪ לשנה |
| `hours_per_month` | `25` | |
| `outstanding_fees` | `55000` | שכר טרחה פתוח (אמצע הטווח) |
| `biggest_leak` / `biggest_leak_label` | `cashflow` / `שכר טרחה תקוע אצל לקוחות` | לפיצול רצפי וואטסאפ לפי כאב |
| `goal` | `scale` / `service` / `family` / `rest` | מה עונה בשאלה 5 |
| `utm_source` … `utm_term`, `page_url` | | ייחוס קמפיין |

**ב-Make:** Custom Webhook ← Redetermine data structure ← למלא את השאלון פעם אחת ← השדות יופיעו למיפוי. אפשר לשים Router לפי `biggest_leak` כדי לשלוח רצף וואטסאפ שונה לכל כאב.

## העלאה ל-uPress / Elementor
- האתר סטטי: `index.html`, `results.html`, `thank-you.html`, `styles.css`, `config.js` ותיקיית `logo/`. אפשר להעלות כמו שהם לתיקייה בשרת.
- ב-Elementor: כל `<section>` הוא בלוק עצמאי שאפשר להדביק בווידג'ט HTML. את `styles.css` מוסיפים פעם אחת (Custom CSS של האתר), ואת `config.js` והסקריפט שבתחתית כל דף מוסיפים בווידג'ט HTML בסוף העמוד.
- השאלון שומר את התוצאה ב-`sessionStorage`, כך ש-`results.html` חייב להיות באותו דומיין.

## הרצה מקומית

```
python3 -m http.server 8531
```
(מריצים מתוך תיקיית הפרויקט ופותחים http://localhost:8531 — לא לפתוח את הקבצים ישירות, כי המעבר לדף התוצאות נשען על sessionStorage באותו דומיין.)

## החלטות (ספטמבר 2026)
- **לידים:** נשלחים ל-**LeadSync** (`receiveWebsiteLead`), לא ל-Make. ב-`config.js` ממלאים `leadWebhookUrl`, `leadFormId` ו-`leadSecretKey` מחיבור הטופס ב-LeadSync. הסקריפט של Google Sheets נשאר כאופציית בדיקה/גיבוי.
- **יומן:** Calendly מחובר ליומן הגוגל. האתר מעביר לדף התודה בעצמו אחרי קביעה (בלי פיצ'ר בתשלום).
- **מיתוג:** כפתורי הזהב נשארים (כמו באתר הראשי); הדגשות ה-AI באקווה (#2DD4BF) והצלחה באמרלד (#0E9F6E) לפי הפלטה של NoamG.
- **פונטים:** Heebo ו-Rubik מאוחסנים מקומית ב-`fonts/` (קבצים משתנים, תת-קבוצות עברית ולטינית) ונטענים מ-`fonts.css`, בלי תלות ב-Google Fonts בזמן הטעינה.
- **שליחת לידים עמידה:** בדיקת תשובת השרת, ניסיון שני ללא CORS, ושמירה ב-localStorage עם ניסיון חוזר מדף התוצאות/התודה. שדה מלכודת (`website`) חוסם בוטים פשוטים.

## עדכון גרסה (Cache)
הקישורים ל-`styles.css`, ל-`config.js` ול-`fonts.css` כוללים `?v=3`. אחרי כל שינוי בקבצים האלה, להעלות את המספר (`?v=4` וכן הלאה) בשלושת הדפים, כדי שגולשים לא יקבלו גרסה ישנה מהמטמון.
